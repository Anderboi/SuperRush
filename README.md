# РЫВОК — Unity Starter (MVP-ядро)

Играбельное ядро из GDD на примитивах: вид из-за спины, герой по центру, препятствия идут в 3 полосах × 3 высотах, свайп в направлении угрозы уничтожает переднее препятствие. Комбо, очки, жизни, рост скорости/сложности, отладочный HUD. **Никаких ассетов не нужно** — всё строится из примитивов в рантайме.

Цель этого среза — проверить, что кор-механика «свайп-уничтожение» в 3D фановая и читаемая (MVP-задача из GDD).

---

## Требования

- **Unity 6 LTS** (подойдёт и 2022.3 LTS).
- **URP или Built-in** — без разницы, материалы создаются под оба пайплайна.

## Установка (5 минут)

1. Создай новый Unity-проект (шаблон **URP** или **3D Built-in** — любой).
2. **Project Settings → Player → Other Settings → Active Input Handling = `Both`.**
   Важно: ядро ввода использует legacy `Input` для нулевого сетапа. (Production-переход на Input System — позже, за тем же интерфейсом `SwipeDetector.OnSwipe`.)
3. Скопируй папку `Assets/_Project` из архива в `Assets/` своего проекта.
4. В пустой сцене создай пустой GameObject (`GameObject → Create Empty`), назови **Bootstrap**, и добавь на него компонент **Bootstrap** (`Add Component → Bootstrap`).
   - Главную камеру и Directional Light из стандартной сцены трогать не надо — бутстрап их переиспользует.
5. Нажми **Play**.

## Управление

- **Свайп** вверх / вниз / влево / вправо, тап — на телефоне и в Game-вью мышью.
- **Стрелки / WASD** + **Space** (тап) — на клавиатуре.
- **Ультимейт:** клавиша **F** или кнопка «ULT» в HUD, когда шкала заполнена.
- Соответствие: **вверх** = воздушная (жёлтая), **вниз** = низкая (красная), **влево/вправо** = полосы (синие), **тап** = фронт по центру (фиолетовый).
- В меню / после смерти — любой ввод стартует/перезапускает забег.

## Что должно происходить

Кубы-препятствия едут на тебя, цвет и позиция телеграфируют нужный свайп. Верный свайп по переднему препятствию в зоне удара — уничтожение (поп + тряска + очки × комбо). Пропустил препятствие до героя — −1 жизнь (вспышка). Скорость и плотность растут. 0 жизней → Game Over → свайп для рестарта.

**Двухходовки (с средней сложности):** крупное препятствие требует двух свайпов по порядку. Первый верный свайп → оно перекрашивается и пульсирует (окно-стаггер) → добей вторым свайпом за бонус. Не успел — прогресс откатывается без урона.

## Тюнинг

Все числа геймплея — в `Core/Config.cs` (скорость, рост сложности, интервалы спавна, зона удара, позиции полос/высот, окно комбо). Меняй и сразу пробуй.

## Структура

```
Assets/_Project/Scripts/
  Core/      Config, GameState, GameManager, Bootstrap
  Input/     SwipeDirection, SwipeDetector
  Gameplay/  Obstacle, ObstacleSpawner (поле: пул + движение + резолв), HeroController (хост способностей), GroundScroller
  Spawning/  SpawnPattern (ScriptableObject-волна), SpawnDirector (выбор паттернов под сложность)
  Abilities/ Ability, StrikeAbility, Passive/ChainPassive, Ultimate/ScreenClearUltimate (всё SO)
  Heroes/    HeroData (SO), HeroLibrary (Вольт в коде для zero-setup)
  Scoring/   ComboManager
  Feel/      CameraShake, Vfx, HitStop, MaterialUtil
  UI/        HudDebug (OnGUI, временный — очки/жизни/комбо/шкала ульты)
```

## Чего здесь намеренно НЕТ (по дорожной карте GDD)

Героев/меты и 4-ростера, двухходовых препятствий (7.1), боссов, реального арта/звука, TMP-HUD, Input System, рекламы/IAP. Это MVP — только доказать фан кор-лупа.

- ~~двухходовки (7.1): у `Obstacle` уже задел — добавить упорядоченную последовательность стадий + окно-стаггер.~~ ✅ **Готово (путь A — позиционная двухходовка):** `Obstacle` стал многостадийным. Двухходовое препятствие крупнее (читается как особое), требует два свайпа по порядку. Первый верный свайп открывает **окно-стаггер** (`Config.StaggerWindow`) — препятствие перекрашивается в цвет 2-го ввода и пульсирует; второй свайп добивает с **бонусом** (очки + лишний тик комбо). Не успел во 2-ю стадию — прогресс **откатывается** (не мгновенный урон, GDD §7.1). Двухходовки — «специя»: только в паттернах от средней сложности (`Charge-Up`, `Double-Trouble`). Слот паттерна расширен полем `second`.
